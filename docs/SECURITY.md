# Security boundaries

Phase 1 runs entirely as the current user. It cannot back up unreadable root-owned data or prove complete-system recovery. No privileged helper, polkit rule, fstab edit, lingering or automatic deletion is installed.

Repository passwords are stored under Secret Service attributes `application=nyx-backup`, `account=DESTINATION_ID`, `kind=repository`. A Restic `--password-command` performs the lookup into a pipe. SMB credentials are stored with `kind=smb`. Each encrypted Rclone configuration has a random 256-bit unlock secret stored with `kind=rclone`; NAS passwords reach `rclone obscure -` through stdin. No password is put in argv, environment values, TOML, job state or logs. Inherited `RESTIC_*`/`RCLONE_*` variables are stripped from child commands to prevent backend/password overrides.

Rclone files use the standard `RCLONE_ENCRYPT_V0` format: SHA256(`[ASCII_RANDOM_PASSWORD][rclone-config]`) as the XSalsa20-Poly1305 key, with an independent 192-bit random nonce. Only cryptographic ciphertext reaches disk. The generated ASCII password avoids normalization ambiguity. Native Rclone decoding is part of the disposable fixture. Obscuring alone is not treated as encryption. Secrets are not guaranteed to be zeroized from process memory; same-user debuggers and a compromised desktop/keyring are outside this boundary.

Secret Service must be available/unlocked. Failed lookup is a failed job; it never generates a replacement password or initializes a replacement repository. Recovery-password export is explicit, uses create-new semantics and mode 0600, and refuses to overwrite a file. Keep the export separately from both the computer and backup destination.

Local-folder destinations are intentionally unbound. For removable media use mounted destinations: exact mount point, filesystem type and mount source must match; block devices additionally require a matching filesystem UUID. A missing device cannot fall through into the bare mount directory. Repository symlink escapes are rejected against the checked mount. NFS connection uses the exact existing user/users fstab definition and invokes unprivileged mount/umount; it never constructs system definitions. A physical unmount racing an operation remains possible; do not disconnect storage during a job. Application-managed NFS disconnect takes the worker lock.

SFTP supplies `BatchMode` and connection timeout to SSH, retaining the user's host verification and authentication configuration. Unknown hosts must be approved outside Backup. SMB uses an app-owned encrypted Rclone config with a Secret Service unlock helper, without putting NAS passwords into repository URLs. Host/share/user metadata is ordinary configuration; it is not a secret value. Child diagnostics are suppressed rather than persisted because transports can include sensitive diagnostics. Failures retain exit status and actionable categories; this is less detailed than a native Restic diagnostic session.

Recognized private keys, secret stores and credential locations are outside defaults. Explicit profile authorization includes recognized credential paths in the encrypted backup. Files with arbitrary names can still contain secrets. Recognized database/container/VM stores remain excluded; SQLite headers catch some stores without filename extensions. Active WAL/process-descriptor/database markers block execution. Detection cannot prove application consistency, detect every store, or freeze a live filesystem. Stop applications or use proper exports. Metadata itself can reveal usernames, mount names and boot parameters and is included inside the encrypted snapshot.

Selection uses non-following directory traversal and passes NUL-separated paths through Restic's `--files-from-raw` stdin, avoiding shell interpolation and option injection. The selection may change between scan and execution. It is not a filesystem snapshot. Directory entries can change concurrently; encrypted backup authorization applies to the selected folders.

Retention requires explicit confirmation and is restricted to both Backup/profile tags. Snapshot IDs and tags are standard Restic metadata; a user deliberately editing tags can alter that scope. No automatic prune or unlock is run. The session API rejects unapproved profiles and all initialization, deletion, mutation, restore, credential retrieval and arbitrary-command requests. UID checks do not grant trust to external/remote callers. Any future Core Control integration must preserve these receiving-app checks.

References: [Restic password-command](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html), [Rclone SMB](https://rclone.org/smb/), [Rclone encryption](https://rclone.org/docs/#configuration-encryption).
